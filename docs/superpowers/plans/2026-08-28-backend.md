# Backend `photo_ui` — plan d'implémentation

> **Pour les agents exécutants :** SOUS-COMPÉTENCE REQUISE — utiliser
> `superpowers:subagent-driven-development` (recommandé) ou
> `superpowers:executing-plans` pour dérouler ce plan tâche par tâche. Les
> étapes sont en cases à cocher (`- [ ]`).

**But :** servir `docs/api-contract.md` depuis PostgreSQL, à partir des quatre
bases SQLite du pipeline lues en lecture seule, avec la cascade de datation
matérialisée à l'import et l'export d'un dossier de tâche sur disque.

**Architecture :** couches `controllers → metier → repository → db`, sans saut.
Composition root explicite dans `bootstrap.ts`, aucun conteneur de DI.
Mono-thread : le seul parallélisme est celui des processus enfants `sips` et de
l'entrée-sortie asynchrone. La règle capitale — une inférence ne doit jamais
ressembler à une lecture — est tenue par une **colonne générée** que PostgreSQL
refuse de laisser écrire, pas par une convention.

**Pile :** Node 24 · TypeScript strict · Fastify · `pg` + `pg-copy-streams` ·
`node:sqlite` (lecture seule) · `sips` · Vitest.

**Spécification :** `docs/backend-spec.md` (le comment) et
`docs/api-contract.md` (le quoi, **gelé**). Les deux voyagent avec ce plan ;
un exécutant lit les trois.

## Contraintes globales

Ces valeurs sont reprises **verbatim** des documents normatifs. Elles font
implicitement partie des exigences de chaque tâche.

| Contrainte | Valeur exacte |
|:---|:---|

| Base | `photo_ui`, utilisateur `nico`, mot de passe `Funiculi`, collation ICU `fr-FR` |

## Décisions d'architecture, et leurs raisons

Écrites ici pour survivre au contexte qui les a prises. Un successeur reprend
sans re-décider.

### D1 — `server/` isolé, avec son propre `package.json`

**Convenu avec `impl-frontend` le 2026-08-28.** Le dépôt porte déjà un frontend
Vite dont le `package.json` est à la racine. Le backend vit **entièrement** sous
`server/`, avec son propre manifeste, son `tsconfig.json` et son
`vitest.config.ts`.

*Pourquoi :* deux jeux de dépendances dans un seul `package.json` produisent un
conflit sur `package-lock.json` à chaque `npm install` de l'un ou de l'autre —
le conflit de fusion le plus pénible qui soit, et le plus fréquent. Des
workspaces npm à la racine résoudraient le problème mais déplaceraient le
`package.json` du frontend, remaniement refusé à ce stade.

*Conséquence :* la disposition de `docs/backend-spec.md` §2.1 (`src/runtime/`,
`src/http/`…) est décalée sous `server/src/`. **C'est la seule divergence de
disposition, et elle est sans effet sur le découpage en couches.**

### D2 — Les valeurs codées ont une seule définition, les interfaces peuvent en avoir deux

`server/` importe `src/shared/enums.ts` et `src/shared/date_interface.ts` **en
lecture seule**, par l'alias `@shared/*`. Les interfaces que le frontend n'a pas
encore transcrites sont transcrites dans `server/src/contract/`.

*Pourquoi cette asymétrie :* une valeur codée transcrite deux fois peut diverger
**silencieusement** (`passage_date_from` contre `passage_date` : les deux
compilent, un seul est juste). Une interface transcrite deux fois ne peut pas :
le client valide en `zod.strictObject` et **lève** en nommant le champ. Le
contrat a prévu ce détecteur ; on s'appuie dessus pour les formes, on refuse d'y
recourir pour les valeurs.

### D3 — `node:sqlite`, pas `better-sqlite3`

**Vérifié** sur Node 24.18 : `new DatabaseSync(path, { readOnly: true })` ouvre
`documents.db` et lit ses 1 859 passages.

*Pourquoi :* supprime une dépendance native à compiler. Rejoint la réserve de la
question ouverte n° 3 de la spec sur `sharp` et Capacitor.

### D4 — PostgreSQL 17.6 (question ouverte n° 1 de la spec, tranchée)

*Pourquoi :* rien dans la spec n'exige la 18, et la base **existe déjà** en
17.6. La spec demandait de trancher avant la première migration parce que
revenir en arrière sur une base peuplée coûte plus cher que le contraire.

### D5 — L'import est **une** transaction (question ouverte n° 2, défaut (a))

*Pourquoi :* `TRUNCATE` est transactionnel en PostgreSQL ; un import qui échoue
à mi-parcours laisse la base exactement dans son état précédent, sans reprise ni
nettoyage. Le prix est un verrou de plusieurs minutes sur `pipeline`, accepté :
l'utilisateur déclenche lui-même l'import et sait qu'il tourne.

### D6 — `app.text_search` est une vue matérialisée (question ouverte n° 4)

*Pourquoi :* la frontière `pipeline` / `app` vaut plus que le coût d'un
`REFRESH` sur 2 871 lignes. **À vérifier à l'implémentation** (incertitude n° 6
de la spec) : si `REFRESH … CONCURRENTLY` est refusé dans la transaction
d'écriture d'une correction, replier sur un `REFRESH` non concurrent, qui pose
un verrou exclusif de quelques millisecondes.

### D7 — Le DDL de la spec est **vérifié**, plus supposé

Exécuté le 2026-08-28 sur la vraie base, dans une transaction, schéma jetable
nettoyé après. Lève l'**incertitude n° 1** de `docs/backend-spec.md` §17 :

| Vérifié | Résultat |
|:---|:---|
| `CREATE TEXT SEARCH CONFIGURATION fr_unaccent` + `ALTER MAPPING` | OK |
| Colonne générée `to_tsvector('fr_unaccent', …) STORED` | **acceptée** |
| `daterange` généré + index GiST | OK |
| `CHECK` mois-entier / année-entière avec `extract` | OK, et **rejettent** `[2004-09-14, 2004-09-14]` en `precision: 'month'` |
| `UPDATE … SET resolved_kind = 'reading'` | **`ERROR: column "resolved_kind" can only be updated to DEFAULT`** |
| `resolved_range && daterange('2000-12-01','2000-12-20','[]')` | ramène l'album au mois entier — le cas des 273 |
| `U&'Alge\0300s' = 'Algès'` | **faux** (6 caractères contre 5) ; `normalize(…, NFC)` répare |

Chiffres normatifs revérifiés sur les vraies bases : **456** collisions
`passages.id` ∩ `log_entries.id`, **82 albums / 3 930 photos** sur les cinq sets.

### D8 — Le manifeste suit les valeurs du contrat — **tranché par `contrat-api`**

L'annexe C de `docs/frontend-spec.md` écrivait `passage_date`,
`logbook-interpolated`, `date-range` et `rule: "B"` là où le contrat §2 dit
`passage_date_from`, `logbook_interpolated`, `date_range` et `passage`.

**Le contrat gagne, dans le manifeste aussi.** Deux raisons, la seconde de
`contrat-api` et plus forte que la mienne :

1. Une table de correspondance de **valeurs** est ce que la spec §4.3 refuse
   déjà pour `human`/`annotation` — « un endroit où se glisse une faute, pour un
   bénéfice nul ». On ne peut pas unifier là et se diviser ici.
2. **`"rule": "B"` trahit l'autosuffisance du manifeste.** « B » renvoie à une
   section de spec que le lecteur du dossier livré n'a pas, alors que la
   propriété n° 4 du contrat §7.4 exige un dossier déplaçable et envoyable tel
   quel. `"passage"` se comprend seul.

**Et une règle de forme, désormais explicite** — ce que j'avais pris pour une
incohérence n'en était pas une :

| Forme | Sens | Où |
|:---|:---|:---|
| `{start, end, precision, kind, source, bracket_hours}` | un `ResolvedDate` — le système **affirme** | `images[].date`, `texts[].date` |
| `{from, to}` | un intervalle simple, qui **n'affirme rien** | `task.period` (une question), `texts[].overlap` (une fenêtre calculée) |

Donc `texts[].date` passe en `start`/`end` **et porte `precision`** (`'day'`
dans tous les cas connus — raison de la rendre constante, pas de l'omettre) et
`bracket_hours: null`. `texts[].overlap` garde `from`/`to`.

*Conséquence :* `metier/export/` ne contient **qu'une conversion de casse et un
ordre de clés**. C'est exactement ce qu'un test d'idempotence peut couvrir.

### D10 — Le `CHECK` de précision teste l'alignement des bornes, pas la largeur

**Tranché : `contrat-api` a repris le correctif mot pour mot dans
`backend-spec.md` §4.3.** Le `CHECK` de la spec **rejetait l'exemple phare de la
spec elle-même** — mesuré :

`ref.album_span` sur `1998-02-Maison rose Algès` vaut `[1998-02-01, 1999-06-30]`
(dix-sept mois). Une photo de cet album sans EXIF est au rang 5,
`resolved_from = 'album_month'`, intervalle = le span saisi. Aucune valeur de
`resolved_precision` n'est jouable :

| Précision | Résultat |
|:---|:---|
| `'month'` | **rejetée** — `photo_month_is_whole_month` exige `end = start + 1 mois − 1 jour` |
| `'year'` | **rejetée** — le `CHECK` année exige une année civile pleine |
| `'day'` | acceptée par la base, mais `formatResolvedDate` rend `date.start` seul : la photo s'afficherait **`1998-02-01`**, un jour inventé au backend — ce que la règle 4 de « Besoins pour le backend » interdit |

*Le diagnostic :* le `CHECK` mesure **la largeur** alors que le contrat §2.2 dit
que `precision` qualifie **chaque borne**. Il confond les deux notions que le
contrat sépare. Pour un span saisi, les deux bornes sont connues au mois :
`precision: 'month'` est la description juste, la largeur est libre.

```sql
CONSTRAINT photo_month_is_whole_month CHECK (
  resolved_precision <> 'month' OR (
    extract(day from resolved_start) = 1
    AND resolved_end = (date_trunc('month', resolved_end::timestamp)
                        + interval '1 month' - interval '1 day')::date)),
CONSTRAINT photo_year_is_whole_year CHECK (
  resolved_precision <> 'year' OR (
    extract(doy from resolved_start) = 1
    AND resolved_end = (date_trunc('year', resolved_end::timestamp)
                        + interval '1 year' - interval '1 day')::date))
```

**Vérifié sur la base.** Le correctif **ne perd rien** de ce que le `CHECK`
protégeait :

| Cas | Strict (spec) | Aligné (retenu) |
|:---|:---|:---|
| `[1998-02-01, 1999-06-30]` en `month` — le span saisi | rejeté | **accepté** |
| `[2000-12-01, 2000-12-31]` en `month` — le mois simple | accepté | accepté |
| `[2004-09-14, 2004-09-14]` en `month` — le jour arbitraire | rejeté | **rejeté** |

*Question corollaire, tranchée aussi :* pas de sixième valeur `album_span` dans
`DateSource`. Ma symétrie s'appuyait sur `ref.web_span = decision`, or **Nicolas
a tranché depuis : `web_span` est une `inference`**. Le critère retenu :

> Ce qui distingue une décision d'une inférence n'est pas **qui** a agi mais
> **ce que le geste établit**. Une annotation de datation *arbitre* — quelqu'un
> a vu l'EXIF et a tapé autre chose. Une plage *comble un vide*.

Un `ref.album_span` comble un vide comme un `web_span` : la personne borne un
album dont on ne sait rien de précis, et le résultat est un intervalle au mois.
Donc `album_month` / `inference`. **`annotation` est la seule source de nature
`decision`** — le `CASE` SQL ne pose `decision` que là.

### D11 — Un texte affirme un jour, ou rien

**Trois contraintes ajoutées par `contrat-api`** sur `pipeline.text_unit`, prises
dans la migration initiale (base non peuplée, donc aucun `ALTER TABLE`) :

```sql
CONSTRAINT text_date_source_is_a_reading CHECK (
  date_source IS NULL OR date_source IN ('passage_date_from','log_entry_date')),
CONSTRAINT text_date_is_a_single_day CHECK (date_start = date_end),
CONSTRAINT text_date_complete CHECK ((date_source IS NULL) = (date_start IS NULL))
```

`date_kind` généré perd deux branches : il ne produit plus que `'reading'` ou
NULL.

*Pourquoi :* une fenêtre de page ou un `ref.web_span` est **ce qu'on a calculé
autour du texte**, pas ce qu'il dit. Ça vit dans `covers_*`, où
`page_span_source` le qualifie déjà. Avec ces contraintes, **toute date de texte
du système est une lecture, et la base le garantit** — la phrase « l'incertitude
est entièrement du côté des images » cesse d'être une approximation. Même
mécanisme que `resolved_kind` sur les photos.

*Conséquence sur l'import :* pour un passage sans `dateFrom`, laisser
`date_source`, `date_start`, `date_end` à **NULL** et ne remplir que
`covers_start` / `covers_end` / `covers_rule`.

*Conséquence sur le manifeste :* `texts[].date` peut être `null`, et c'est le
cas **normal** — plus d'un tiers des unités. Quand il ne l'est pas :
`start == end`, `precision: "day"`, `kind: "reading"`, `bracket_hours: null`.

**`page_window` et `web_span` restent des `DateSource` valides du contrat** — ils
qualifient `page.window_*` et le span d'un document web, pas `text_unit.date_*`.
Ne pas les retirer du vocabulaire partagé.

*Comptes vérifiés par moi sur `documents.db`, les huit tombent juste :*

| | Attendu | Mesuré |
|:---|---:|---:|
| total `text_unit` | 2 871 | **2 871** |
| passages · entrées | 1 859 · 1 012 | **1 859 · 1 012** |
| passages avec `dateFrom` | 828 | **828** |
| **avec une date** | 1 840 | **1 840** |
| **sans date** | 1 031 | **1 031** |
| dont web · dont datées par leur page | 569 · 462 | **569 · 462** |
| les 462, par `spanSource` | 341 `entries` + 121 `carried` | **341 + 121** |

## Le plan de tests

Livrable au même niveau que le plan d'implémentation.

### Deux projets Vitest, deux natures

| Projet | Fichiers | Base | Ce qu'il prouve |
|:---|:---|:---|:---|
| `unit` | `src/**/*.test.ts` | **aucune** | les règles pures : cascade, arbitrage, recouvrement, nettoyage de `q`, offsets, sérialisation canonique, `content_hash`, slug, allowlist |
| `integration` | `src/**/*.itest.ts` | **réelle** | le schéma, les requêtes, l'import, l'export, les invariants transverses |

La majeure partie de ce qui mérite un test est **pure** et ne touche à rien.
Aucune moquerie n'est nécessaire, et c'est le signe que le découpage est bon :
là où il faudrait moquer un `repository`, c'est qu'une règle a fui dans la
mauvaise couche.

### Le jeu d'essai d'intégration — une instance de chaque piège

`server/test/fixtures/seed.sql` construit une quarantaine de photos, trois
albums, deux documents et une trentaine de textes. La base de test n'est **pas**
une copie de la vraie : celle-ci fait 3 930 photos et vit sur un volume
démontable.

| Piège | Ce que le jeu d'essai contient |
|:---|:---|
| NFD / NFC | un `album_path` avec `Algès` décomposé |
| Collision d'identifiants | `logbook/p003/001` en `passage` **et** en `log_entry`, textes différents |
| Date de scan | un EXIF 2017 dans un album `2000-12` |
| Album à année seule | un album `2000` sans mois |
| Photo sans aucune date | une ligne `raw_date_source = 'none'` |
| **Le cas des 273** | un album au mois dont l'intervalle dépasse la borne haute d'un filtre |
| Fenêtre `carried` | une page dont `span_source = 'carried'` |
| `sha256` partagé | deux photos, un seul contenu, une seule vignette |
| Position absente mais nommée | une entrée de journal avec `place_name` et sans coordonnées |

**Cycle :** migrations appliquées une fois, puis **chaque test dans une
transaction annulée à la fin**. Isolation parfaite, pas de `TRUNCATE` entre les
tests, suite rapide.

### Les neuf invariants qui méritent leur propre fichier

Tests de **règle**, pas de fonction. Ils échouent quand quelqu'un a raison
localement et tort globalement.

1. **Une inférence ne peut jamais être servie comme une lecture** —
   `src/invariants/capital_rule.itest.ts`. Le test qui compte le plus du projet,
   à trois niveaux : *schéma* (l'`UPDATE` sur la colonne générée lève), *cascade*
   (les six rangs donnent exactement le `kind` annoncé, un `resolved_from`
   inconnu est rejeté par le `CHECK`), *contrat* (parcours récursif de chaque
   corps de réponse : **aucune clé nommée `date` ne porte une chaîne**, et tout
   objet portant `start` et `end` porte aussi `kind`, `source`, `precision`).
2. **Un filtre ne disparaît jamais** — paramètre mal orthographié → 400 en le
   nommant ; valeur inconnue d'un vocabulaire ouvert → 200, `total: 0`,
   `unmatchedValues` ; `q` réduit à rien → `total: 0` et **jamais** la
   population entière.
3. **Chevauchement, jamais inclusion** — le filtre `2000-12-01 → 2000-12-20`
   ramène l'album `[2000-12-01, 2000-12-31]`. Une lecture stricte en rend 0.
   C'est la régression la plus coûteuse possible, et elle est silencieuse.
4. **La clé d'un texte est le couple** — corriger `(passage, logbook/p003/001)`
   ne change rien à `(log_entry, logbook/p003/001)`, ni en base ni dans la
   réponse.
5. **L'import ne touche pas au travail humain** — importer, créer une tâche avec
   sélections, corrections et légendes, réimporter : tout est intact, les
   orphelins sont **marqués**, la table n'a pas perdu une ligne.
6. **Aucune FK de `app` vers `pipeline`** — un test interroge
   `information_schema` et échoue si une contrainte référentielle traverse les
   deux schémas. Bon marché, et empêche la régression qui détruirait le travail
   humain au prochain `TRUNCATE`.
7. **L'export est idempotent** — exporter deux fois, comparer les arbres octet
   par octet : seul `exported_at` diffère.
8. **Rien n'est écrit hors des racines inscriptibles** — empreinte de
   `ORIGINALS_ROOT` et `THUMBS_ROOT` relevée avant et après un rendu, une
   pré-construction et un export complets.
9. **NFC** — une recherche d'album tapée en NFC trouve l'album stocké depuis une
   source NFD.

### Ce qui n'est pas testé, et pourquoi

```ts
export const LogLevel = {
  DEBUG: 'debug', INFO: 'info', WARN: 'warn', ERROR: 'error',
} as const;
export type LogLevel = (typeof LogLevel)[keyof typeof LogLevel];

export interface Log {
  debug(message: string, fields?: Record<string, unknown>): void;
  info(message: string, fields?: Record<string, unknown>): void;
  warn(message: string, fields?: Record<string, unknown>): void;
  error(message: string, fields?: Record<string, unknown>): void;
  child(fields: Record<string, unknown>): Log;
}

const RANK: Record<LogLevel, number> = { debug: 10, info: 20, warn: 30, error: 40 };

export function createLog(level: LogLevel, base: Record<string, unknown> = {},
                          sink: (line: string) => void = writeLine): Log {
  const emit = (at: LogLevel, message: string, fields?: Record<string, unknown>): void => {
    if (RANK[at] < RANK[level]) return;
    sink(JSON.stringify({ at: new Date().toISOString(), level: at, message, ...base, ...fields }));
  };
  return {
    debug: (m, f) => emit(LogLevel.DEBUG, m, f),
    info: (m, f) => emit(LogLevel.INFO, m, f),
    warn: (m, f) => emit(LogLevel.WARN, m, f),
    error: (m, f) => emit(LogLevel.ERROR, m, f),
    child: (fields) => createLog(level, { ...base, ...fields }, sink),
  };
}

function writeLine(line: string): void {
  process.stdout.write(line + '\n');
}
```

```ts
export interface Config {
  readonly host: string;
  readonly port: number;
  readonly databaseUrl: string;
  readonly originalsRoot: string;
  readonly thumbsRoot: string;
  readonly pipelineDbRoot: string;
  readonly pagesRoot: string;
  readonly annotationsDir: string;
  readonly renderCacheRoot: string;
  readonly tasksRoot: string;
  readonly periodFrom: string;
  readonly periodTo: string;
  readonly perimeterSets: readonly string[];
  readonly renderEdge: number;
  readonly renderConcurrency: number;
  readonly featureDatingExport: boolean;
  readonly logLevel: LogLevel;
}

const DEFAULT_PERIMETER_SETS = ['1998-1999', '2000-2001', '2002', '2003', '2004'] as const;

export function loadConfig(env: NodeJS.ProcessEnv): Config {
  const missing: string[] = [];
  const required = (name: string): string => {
    const value = env[name];
    if (value === undefined || value.trim() === '') { missing.push(name); return ''; }
    return value;
  };
  const integer = (name: string, fallback: number): number => {
    const raw = env[name];
    if (raw === undefined || raw.trim() === '') return fallback;
    const parsed = Number(raw);
    if (!Number.isInteger(parsed)) {
      throw new Error(`${name} doit être un entier, reçu ${JSON.stringify(raw)}`);
    }
    return parsed;
  };

  const config: Config = {
    host: env.PHOTO_UI_HOST ?? '127.0.0.1',
    port: integer('PHOTO_UI_PORT', 4310),
    databaseUrl: required('DATABASE_URL'),
    originalsRoot: required('ORIGINALS_ROOT'),
    thumbsRoot: required('THUMBS_ROOT'),
    pipelineDbRoot: required('PIPELINE_DB_ROOT'),
    pagesRoot: required('PAGES_ROOT'),
    annotationsDir: required('ANNOTATIONS_DIR'),
    renderCacheRoot: required('RENDER_CACHE_ROOT'),
    tasksRoot: required('TASKS_ROOT'),
    periodFrom: env.PERIOD_FROM ?? '1998-01-01',
    periodTo: env.PERIOD_TO ?? '2004-12-31',
    perimeterSets: env.PERIMETER_SETS?.split(',').map((s) => s.trim())
      ?? [...DEFAULT_PERIMETER_SETS],
    renderEdge: integer('RENDER_EDGE', 1400),
    renderConcurrency: integer('RENDER_CONCURRENCY', 8),
    featureDatingExport: env.FEATURE_DATING_EXPORT === 'true',
    logLevel: (env.LOG_LEVEL ?? 'info') as LogLevel,
  };

  if (missing.length > 0) {
    throw new Error(`variables d'environnement manquantes : ${missing.join(', ')}`);
  }
  return config;
}
```

```ts
// server/src/db/transaction.ts
import type { Pool, PoolClient } from './pool.ts';

/**
 * LA frontière transactionnelle. Un repository n'en ouvre jamais, un
 * contrôleur non plus : les erreurs remontent jusqu'ici, puis rollback.
 */
export async function withTransaction<T>(
  pool: Pool,
  fn: (client: PoolClient) => Promise<T>,
): Promise<T> {
  const client = await pool.connect();
  try {
    await client.query('BEGIN');
    const result = await fn(client);
    await client.query('COMMIT');
    return result;
  } catch (error) {
    await client.query('ROLLBACK').catch(() => undefined);
    throw error;
  } finally {
    client.release();
  }
}
```

```ts
// server/src/db/migrate.ts
import { readdir, readFile } from 'node:fs/promises';
import path from 'node:path';
import type { Log } from '../log/log.ts';
import type { Pool } from './pool.ts';
import { withTransaction } from './transaction.ts';

export async function runMigrations(pool: Pool, log: Log, directory: string): Promise<string[]> {
  await pool.query(`CREATE TABLE IF NOT EXISTS public.schema_migration (
    version text PRIMARY KEY, applied_at timestamptz NOT NULL DEFAULT now())`);

  const files = (await readdir(directory)).filter((f) => f.endsWith('.sql')).sort();
  const { rows } = await pool.query<{ version: string }>('SELECT version FROM public.schema_migration');
  const applied = new Set(rows.map((r) => r.version));
  const ran: string[] = [];

  for (const file of files) {
    const version = file.replace(/\.sql$/, '');
    if (applied.has(version)) continue;
    const sql = await readFile(path.join(directory, file), 'utf8');
    await withTransaction(pool, async (client) => {
      await client.query(sql);
      await client.query('INSERT INTO public.schema_migration (version) VALUES ($1)', [version]);
    });
    log.info('migration appliquée', { version });
    ran.push(version);
  }
  return ran;
}
```

```ts
import { createWriteStream as nodeCreateWriteStream, type WriteStream } from 'node:fs';
import { mkdir, realpath, rename, rm, writeFile } from 'node:fs/promises';
import path from 'node:path';
import { AppError } from '../contract/error_interface.ts';
import { ErrorCode } from '@shared/enums';
import type { Log } from '../log/log.ts';

export interface SafeFs {
  assertWritable(target: string): void;
  writeFile(target: string, data: string | Uint8Array): Promise<void>;
  mkdir(target: string): Promise<void>;
  rename(from: string, to: string): Promise<void>;
  rm(target: string): Promise<void>;
  createWriteStream(target: string): WriteStream;
}

export async function createSafeFs(writableRoots: readonly string[], log: Log): Promise<SafeFs> {
  // Canonicaliser AU DÉMARRAGE : un lien symbolique dans la racine elle-même
  // rendrait toute comparaison de préfixe fausse par la suite.
  const roots = await Promise.all(writableRoots.map((r) => realpath(r)));
  log.info('racines inscriptibles', { roots });

  const inside = (resolved: string): boolean =>
    roots.some((root) => resolved === root || resolved.startsWith(root + path.sep));

  const assertWritable = (target: string): void => {
    if (!inside(path.resolve(target))) {
      throw new AppError(ErrorCode.INTERNAL, `écriture refusée hors racine : ${target}`, 500,
                         { traceId: 'safe-fs' });
    }
  };

  // Un chemin peut être valide lexicalement et sortir par un lien symbolique.
  // On résout le plus long préfixe EXISTANT, puis on re-vérifie.
  const assertResolvedWritable = async (target: string): Promise<void> => {
    assertWritable(target);
    let probe = path.resolve(target);
    for (;;) {
      try { probe = await realpath(probe); break; } catch {
        const parent = path.dirname(probe);
        if (parent === probe) return;
        probe = parent;
      }
    }
    if (!inside(probe)) {
      throw new AppError(ErrorCode.INTERNAL, `écriture refusée hors racine : ${target}`, 500,
                         { traceId: 'safe-fs' });
    }
  };

  return {
    assertWritable,
    async writeFile(target, data) { await assertResolvedWritable(target); await writeFile(target, data); },
    async mkdir(target) { await assertResolvedWritable(target); await mkdir(target, { recursive: true }); },
    async rename(from, to) { await assertResolvedWritable(from); await assertResolvedWritable(to); await rename(from, to); },
    async rm(target) { await assertResolvedWritable(target); await rm(target, { recursive: true, force: true }); },
    createWriteStream(target) { assertWritable(target); return nodeCreateWriteStream(target); },
  };
}
```

```ts
import { ErrorCode } from '@shared/enums';
import { AppError } from '../contract/error_interface.ts';
import type { AppliedFilter } from '../contract/filter_interface.ts';

export type ParamRule =
  | { kind: 'closed'; values: readonly string[]; default?: string }
  | { kind: 'openList' }
  | { kind: 'open' }
  | { kind: 'isoDate' }
  | { kind: 'boolean'; default?: boolean }
  | { kind: 'integer' };
export type ParamSpec = Record<string, ParamRule>;

const ISO_DATE = /^\d{4}-\d{2}-\d{2}$/;

export function parseQueryParams(
  raw: Record<string, unknown>,
  spec: ParamSpec,
): Record<string, unknown> & { applied: AppliedFilter[] } {
  const accepted = Object.keys(spec).sort();
  const unknown = Object.keys(raw).filter((name) => !(name in spec));
  if (unknown.length > 0) {
    throw new AppError(ErrorCode.UNKNOWN_PARAMETER,
      `paramètre inconnu : ${unknown.join(', ')}`, 400,
      { parameters: unknown, accepted });
  }

  const invalid = (parameter: string, received: string, values: readonly string[] | null): never => {
    throw new AppError(ErrorCode.INVALID_PARAMETER,
      `valeur invalide pour ${parameter} : ${received}`, 400,
      { parameter, received, accepted: values });
  };

  const out: Record<string, unknown> = {};
  const applied: AppliedFilter[] = [];

  for (const [name, rule] of Object.entries(spec)) {
    const value = raw[name];
    if (value === undefined) {
      if (rule.kind === 'closed' && rule.default !== undefined) out[name] = rule.default;
      if (rule.kind === 'boolean' && rule.default !== undefined) out[name] = rule.default;
      continue;
    }
    switch (rule.kind) {
      case 'closed': {
        const s = String(value);
        if (!rule.values.includes(s)) invalid(name, s, rule.values);
        out[name] = s; applied.push({ parameter: name, values: [s], broadened: false });
        break;
      }
      case 'openList': {
        const list = (Array.isArray(value) ? value : [value]).map(String);
        out[name] = list; applied.push({ parameter: name, values: list, broadened: false });
        break;
      }
      case 'open': {
        const s = String(value);
        out[name] = s; applied.push({ parameter: name, values: [s], broadened: false });
        break;
      }
      case 'isoDate': {
        const s = String(value);
        if (!ISO_DATE.test(s) || Number.isNaN(Date.parse(s))) invalid(name, s, null);
        out[name] = s; applied.push({ parameter: name, values: [s], broadened: false });
        break;
      }
      case 'boolean': {
        const s = String(value);
        if (s !== 'true' && s !== 'false') invalid(name, s, ['true', 'false']);
        out[name] = s === 'true'; applied.push({ parameter: name, values: [s], broadened: false });
        break;
      }
      case 'integer': {
        const s = String(value);
        if (!/^\d+$/.test(s)) invalid(name, s, null);
        out[name] = Number(s); applied.push({ parameter: name, values: [s], broadened: false });
        break;
      }
    }
  }
  return { ...out, applied } as Record<string, unknown> & { applied: AppliedFilter[] };
}
```

```ts
export interface AlbumInterval {
  readonly from: string;
  readonly to: string;
  readonly presumed: boolean;
  readonly precision: 'day' | 'month' | 'year';
}

// `(?!\d)` empêche `\d{1,2}` de mordre dans un nombre plus long : sans lui,
// un hypothétique `2000-2001` produirait un mois 20.
const PREFIX = /^(\d{4})(?:-(\d{1,2})(?!\d))?/;
const DURATION = /\d+\s*(mois|semaines?|jours?|ans?)/i;

export function parseAlbumPrefix(albumName: string): { year: number | null; month: number | null } {
  const match = PREFIX.exec(albumName);
  if (match === null) return { year: null, month: null };
  const year = Number(match[1]);
  const raw = match[2];
  if (raw === undefined) return { year, month: null };
  const month = Number(raw);
  // NN > 12 est un numéro de voyage ou de semaine, pas un mois.
  return { year, month: month >= 1 && month <= 12 ? month : null };
}

const pad = (n: number): string => String(n).padStart(2, '0');
const lastDayOfMonth = (year: number, month: number): number =>
  new Date(Date.UTC(year, month, 0)).getUTCDate();

function startOfMonth(iso: string): string { return `${iso.slice(0, 7)}-01`; }
function endOfMonth(iso: string): string {
  const year = Number(iso.slice(0, 4));
  const month = Number(iso.slice(5, 7));
  return `${iso.slice(0, 7)}-${pad(lastDayOfMonth(year, month))}`;
}

export function albumInterval(
  albumName: string,
  refSpan: { from: string; to: string } | null,
): AlbumInterval | null {
  // Rang 0 : la saisie humaine gagne sur le préfixe, et n'est jamais presumed.
  if (refSpan !== null) {
    if (refSpan.from === refSpan.to) {
      return { from: refSpan.from, to: refSpan.to, presumed: false, precision: 'day' };
    }
    // Élargi, jamais rétréci : rétrécir perdrait des photos.
    return {
      from: startOfMonth(refSpan.from), to: endOfMonth(refSpan.to),
      presumed: false, precision: 'month',
    };
  }

  const { year, month } = parseAlbumPrefix(albumName);
  if (year === null) return null;
  if (month === null) {
    return { from: `${year}-01-01`, to: `${year}-12-31`, presumed: true, precision: 'year' };
  }
  return {
    from: `${year}-${pad(month)}-01`,
    to: `${year}-${pad(month)}-${pad(lastDayOfMonth(year, month))}`,
    presumed: true, precision: 'month',
  };
}

/** Heuristique d'aide à la saisie. Elle TRIE la liste de l'écran de réglage. */
export function isSuspectedRange(albumName: string): boolean {
  if (DURATION.test(albumName)) return true;
  const body = albumName.replace(PREFIX, '').replace(/^[\s-]+/, '');
  const segments = body.split(/\s*-\s*|\s+et\s+/).map((s) => s.trim()).filter((s) => /\p{L}/u.test(s));
  return segments.length >= 2;
}
```

**La règle** (`docs/backend-spec.md` §7.4) :

```
L'EXIF est retenu ⟺ il tombe dans l'intervalle de l'album élargi de 6 mois
                     de chaque côté.
```

Pour un album au mois, la comparaison se fait **en mois entiers** — l'album ne
prétend pas au jour. Pour un album à année seule, la fenêtre porte sur l'année.

L'écart est stocké **des deux côtés**, retenu comme écarté : c'est lui qui
distingue le rang 4 (« l'EXIF existait, c'est une date de scan ») du rang 5
(« il n'y avait pas d'EXIF »), que `resolved_from` seul ne distingue pas.

```ts
import type { AlbumInterval } from './album_span.ts';

export interface Arbitration {
  readonly outcome: 'accepted' | 'rejected';
  readonly gapMonths: number;
  readonly exifDay: string;
}

const WINDOW_MONTHS = 6;

/** Nombre de mois CIVILS entre deux jours, non signé. */
export function monthsBetween(a: string, b: string): number {
  const months = (iso: string): number => Number(iso.slice(0, 4)) * 12 + Number(iso.slice(5, 7)) - 1;
  return Math.abs(months(a) - months(b));
}

/**
 * Le jour civil d'un captureDate amont, LU et jamais converti.
 * Six formats coexistent et 76 % n'ont aucun fuseau ; passer par `new Date`
 * décalerait le jour de ceux qui en ont un.
 */
function civilDay(captureDateLocal: string): string | null {
  const day = captureDateLocal.slice(0, 10);
  return /^\d{4}-\d{2}-\d{2}$/.test(day) ? day : null;
}

export function arbitrate(captureDateLocal: string | null, album: AlbumInterval): Arbitration | null {
  if (captureDateLocal === null) return null;      // rang 5 — pas d'EXIF, et ça se dit
  const exifDay = civilDay(captureDateLocal);
  if (exifDay === null) return null;

  if (album.precision === 'year') {
    const sameYear = exifDay.slice(0, 4) === album.from.slice(0, 4);
    return { outcome: sameYear ? 'accepted' : 'rejected',
             gapMonths: monthsBetween(exifDay, album.from), exifDay };
  }

  // Dans l'intervalle : écart nul. Sinon, la distance à la borne la plus proche.
  const gapMonths = exifDay < album.from ? monthsBetween(exifDay, album.from)
                  : exifDay > album.to   ? monthsBetween(exifDay, album.to)
                  : 0;
  return { outcome: gapMonths <= WINDOW_MONTHS ? 'accepted' : 'rejected', gapMonths, exifDay };
}
```

**La table des rangs** (`docs/backend-spec.md` §7.5) — `kind` est **dérivé par la
base**, jamais posé ici :

| Rang | Échelon | `resolved_from` | Précision | `kind` (généré) |
|---:|:---|:---|:---|:---|
| 1 | Décision humaine — `annotations.jsonl` | `annotation` | jour | **decision** |
| 2 | EXIF arbitré, dans la fenêtre | `exif_arbitrated` | jour | **reading** |
| 3 | Lieu ↔ journal — `dating.proposals` | `logbook_bracket` | jour | inference |
| 4 | Album, EXIF écarté (date de scan) | `album_month` | mois | inference |
| 5 | Album, pas d'EXIF | `album_month` | mois | inference |
| 6 | Album à année seule | `album_year` | année | inference |

**Deux points que la spec ne tranche pas, et que ce plan pose explicitement :**

1. **L'arbitrage est stocké dès qu'il a eu lieu**, quel que soit le rang qui
   gagne — pas seulement aux rangs 2 et 4. La spec §7.4 dit « stocké des deux
   côtés, retenu comme écarté » ; le contrat dit `NULL au rang 5 et hors cascade
   EXIF`, ce qui est **exactement** le cas où `arbitrate` rend `null`. Les deux
   se rejoignent. Bénéfice : les 92 photos qui portent une annotation **et** un
   EXIF gardent l'écart constatable, et « l'arbitrage se voit » vaut aussi
   au rang 1.
2. **Une photo sans album mais avec un EXIF est datée par son EXIF**
   (`exif_arbitrated`, `reading`), avec `arbitration: null` — il n'y avait rien
   contre quoi arbitrer. Sans cette règle, les 373 photos hors hiérarchie que
   la question 5 autorise dans une tâche seraient toutes sans date. Le seul cas
   qui reste `resolved_from: null` est **ni album, ni EXIF, ni annotation, ni
   proposition** — les 420 de la photothèque entière, et le contrat prévoit
   `date: null` pour eux.

```ts
import { DatePrecision, DateSource } from '@shared/enums';
import type { AlbumInterval } from './album_span.ts';
import { arbitrate } from './arbitration.ts';

export interface CascadeInput { /* voir Interfaces ci-dessus */ }
export interface ResolvedCascade { /* voir Interfaces ci-dessus */ }

const UNDATED: ResolvedCascade = {
  resolvedFrom: null, resolvedStart: null, resolvedEnd: null, resolvedPrecision: null,
  arbitrationGapMonths: null, arbitrationOutcome: null, bracketHours: null, evidenceEntryIds: [],
};

export function resolveCascade(input: CascadeInput): ResolvedCascade {
  const { captureDateLocal, album, annotationDate, proposal } = input;

  // L'arbitrage a lieu dès qu'il y a un album ET un EXIF, quel que soit le rang
  // qui gagnera : c'est ce qui rend l'écart constatable même au rang 1.
  const arbitration = album === null ? null : arbitrate(captureDateLocal, album);
  const withArbitration = {
    arbitrationGapMonths: arbitration?.gapMonths ?? null,
    arbitrationOutcome: arbitration?.outcome ?? null,
  };

  // Rang 1 — la main prime SANS CONDITION. Quelqu'un a ouvert la photo,
  // vu l'EXIF affiché, et tapé autre chose : le contredire était le geste.
  if (annotationDate !== null) {
    return { ...UNDATED, ...withArbitration,
      resolvedFrom: DateSource.ANNOTATION, resolvedStart: annotationDate,
      resolvedEnd: annotationDate, resolvedPrecision: DatePrecision.DAY };
  }

  // Rang 2 — l'EXIF retenu par l'arbitrage. Une lecture.
  if (arbitration?.outcome === 'accepted') {
    return { ...UNDATED, ...withArbitration,
      resolvedFrom: DateSource.EXIF_ARBITRATED, resolvedStart: arbitration.exifDay,
      resolvedEnd: arbitration.exifDay, resolvedPrecision: DatePrecision.DAY };
  }

  // Rang 3 — la proposition du journal, avec sa fourchette et ses preuves.
  if (proposal !== null) {
    return { ...UNDATED, ...withArbitration,
      resolvedFrom: DateSource.LOGBOOK_BRACKET, resolvedStart: proposal.date,
      resolvedEnd: proposal.date, resolvedPrecision: DatePrecision.DAY,
      bracketHours: proposal.spanHours, evidenceEntryIds: proposal.evidenceEntryIds };
  }

  // Rangs 4, 5, 6 — l'album. 4 et 5 ne diffèrent que par le bloc d'arbitrage.
  if (album !== null) {
    const isYear = album.precision === 'year';
    return { ...UNDATED, ...withArbitration,
      resolvedFrom: isYear ? DateSource.ALBUM_YEAR : DateSource.ALBUM_MONTH,
      resolvedStart: album.from, resolvedEnd: album.to,
      resolvedPrecision: isYear ? DatePrecision.YEAR
        : album.precision === 'day' ? DatePrecision.DAY : DatePrecision.MONTH };
  }

  // Pas d'album : l'EXIF sert quand même, sans rien contre quoi arbitrer.
  // Sans cette branche, les 373 photos hors hiérarchie seraient sans date.
  const exifDay = captureDateLocal?.slice(0, 10) ?? null;
  if (exifDay !== null && /^\d{4}-\d{2}-\d{2}$/.test(exifDay)) {
    return { ...UNDATED, resolvedFrom: DateSource.EXIF_ARBITRATED,
      resolvedStart: exifDay, resolvedEnd: exifDay, resolvedPrecision: DatePrecision.DAY };
  }

  return UNDATED;
}
```

```ts
/**
 * macOS stocke les noms de fichiers en NFD. Une égalité littérale avec la même
 * chaîne tapée en NFC ne trouve RIEN — mesuré : zéro ligne sur `…Algès` là où
 * un LIKE en rendait 22. `album_path` étant la clé de `ref.album_span`, une clé
 * en deux normalisations est deux clés.
 */
export function normalizeNfc<T>(value: T): T {
  if (typeof value === 'string') return value.normalize('NFC') as T;
  if (Array.isArray(value)) return value.map(normalizeNfc) as T;
  if (value !== null && typeof value === 'object') {
    return Object.fromEntries(
      Object.entries(value as Record<string, unknown>).map(([k, v]) => [k, normalizeNfc(v)]),
    ) as T;
  }
  return value;
}
```

```ts
import { readdir, readFile } from 'node:fs/promises';
import path from 'node:path';

/** `cloudAssetId` → jour civil. Les autres formes sont acceptées en amont mais
 *  ignorées par son unique consommateur : les reprendre inventerait une donnée. */
export async function readAnnotations(dir: string): Promise<Map<string, string>> {
  const files = (await readdir(dir)).filter((f) => f.endsWith('.jsonl')).sort();
  const latestAt = new Map<string, string>();
  const dated = new Map<string, string>();

  for (const file of files) {
    const lines = (await readFile(path.join(dir, file), 'utf8')).split('\n');
    for (const [index, line] of lines.entries()) {
      if (line.trim() === '') continue;
      let parsed: { at?: unknown; kind?: unknown; target?: { type?: unknown; id?: unknown };
                    value?: { date?: unknown } };
      try { parsed = JSON.parse(line); } catch {
        throw new Error(`ligne malformée dans ${file}:${index + 1}`);
      }
      if (parsed.kind !== 'dating' || parsed.target?.type !== 'photo') continue;
      const id = parsed.target.id;
      const date = parsed.value?.date;
      const at = parsed.at;
      if (typeof id !== 'string' || typeof date !== 'string' || typeof at !== 'string') continue;
      // Une photo a bien été datée deux fois en amont : la dernière gagne.
      const seen = latestAt.get(id);
      if (seen === undefined || at >= seen) { latestAt.set(id, at); dated.set(id, date); }
    }
  }
  return dated;
}
```

### Tâche 10 : les trois règles de recouvrement

La date qu'un texte **affirme** et la fenêtre qu'il **couvre** sont deux choses
différentes, et les confondre serait une faute : une entrée de journal du
14 octobre 1999 affirme ce jour-là — c'est une lecture, écrite le jour même sur
la page — mais pour le recouvrement, la règle A lui fait couvrir jusqu'à la
veille de la journée suivante renseignée, **parfois 92 jours**. Écrire cette
extension dans `date_end` transformerait une lecture exacte en une affirmation de
trois mois. D'où deux intervalles, et `date_kind` dérivé du **premier seulement**
(voir D11).

- Créer : `server/src/metier/overlap/covers.ts`

- Produit : `passageCovers(dateFrom: string | null, pageWindow: { start: string; end: string } | null): { start: string; end: string } | null`

- Produit : `webCovers(span: { from: string; to: string } | null): { start: string; end: string } | null`

```ts
export interface CoverWindow { readonly start: string; readonly end: string }

const dayBefore = (iso: string): string => {
  const d = new Date(`${iso}T00:00:00Z`);
  d.setUTCDate(d.getUTCDate() - 1);
  return d.toISOString().slice(0, 10);
};

/**
 * Règle A. Le journal a 241 jours renseignés sur ~1 513 : on photographie au
 * mouillage, on tient le journal en mer. Les écarts vont de 1 à 92 jours, et
 * AUCUN plafond n'est appliqué — un seuil masquerait des recouvrements corrects
 * autant que du bruit, en silence.
 */
export function logbookCovers(days: readonly string[]): Map<string, CoverWindow> {
  const distinct = [...new Set(days)].sort();
  const covers = new Map<string, CoverWindow>();
  for (const [index, day] of distinct.entries()) {
    const next = distinct[index + 1];
    covers.set(day, { start: day, end: next === undefined ? day : dayBefore(next) });
  }
  return covers;
}

/** Règle B. Sa propre date d'abord ; à défaut la fenêtre de sa page ; sinon rien. */
export function passageCovers(
  dateFrom: string | null,
  pageWindow: CoverWindow | null,
): CoverWindow | null {
  if (dateFrom !== null) return { start: dateFrom, end: dateFrom };
  return pageWindow;
}

/** Règle C. Non matérialisée : `ref.web_span` change à tout moment (§8.1). */
export function webCovers(span: { from: string; to: string } | null): CoverWindow | null {
  return span === null ? null : { start: span.from, end: span.to };
}
```

```ts
import { pipeline } from 'node:stream/promises';
import { Readable } from 'node:stream';
import copyFrom from 'pg-copy-streams';
import type { PoolClient } from '../db/pool.ts';

/** Le seul chemin de chargement en masse : le serveur est dans un conteneur et
 *  ne voit pas le volume externe, donc COPY … FROM '<chemin>' est exclu. */
export async function copyRows(
  client: PoolClient, table: string, columns: readonly string[],
  rows: AsyncIterable<readonly unknown[]>,
): Promise<number> {
  let count = 0;
  const source = Readable.from((async function* () {
    for await (const row of rows) { count++; yield encodeTextRow(row) + '\n'; }
  })());
  const sink = client.query(copyFrom.from(
    `COPY ${table} (${columns.join(', ')}) FROM STDIN WITH (FORMAT text)`));
  await pipeline(source, sink);
  return count;
}

/** Format texte de COPY : \N pour NULL, et quatre échappements obligatoires. */
function encodeTextRow(row: readonly unknown[]): string {
  return row.map((value) => {
    if (value === null || value === undefined) return '\\N';
    return String(value)
      .replaceAll('\\', '\\\\').replaceAll('\t', '\\t')
      .replaceAll('\n', '\\n').replaceAll('\r', '\\r');
  }).join('\t');
}
```

> **L'ordre des quatre remplacements n'est pas indifférent** : l'antislash
