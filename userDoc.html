photo_ui — mode d'emploi

Lancer le serveur, l'interface, et charger les données du pipeline dans PostgreSQL.

Projet en cours d'écriture. Ce document décrit les commandes telles qu'elles existent dans le dépôt aujourd'hui. Le backend est en cours d'implémentation : les commandes ci-dessous existent, mais tous les endpoints ne sont pas encore servis. En cas de doute, server/.env.example et les scripts de server/package.json font foi — ils sont tenus à jour par les agents, ce document non.

En bref

# une seule fois : préparer la base
cd server && npm install && npm run db:migrate && npm run db:import

# à chaque session : deux terminaux
cd server && npm run dev     # API sur http://127.0.0.1:4310
npm run dev                  # interface sur http://localhost:5173

Le disque externe doit être monté pour l'import et pour l'affichage des images. Le serveur y lit les quatre bases du pipeline, les vignettes et les photos originales. Il n'y écrit jamais rien, caches compris.

Toute la configuration passe par des variables d'environnement — aucun chemin n'est écrit en dur dans le code, pour que le backend puisse déménager sur une autre machine sans modification.

Charger les données dans PostgreSQL

Oui, il faut le faire, et c'est en deux temps. La base est vide au départ : le schéma n'existe pas et aucune donnée du pipeline n'y est.

1

Créer le schéma

cd server
npm install
npm run db:migrate

Crée les trois schémas et leurs contraintes. pipeline reçoit la copie des données du pipeline, app vos décisions et vos tâches, ref les référentiels corrigeables à la main.

2

Importer

npm run db:import

Lit les quatre bases SQLite du pipeline en lecture seule, plus annotations.jsonl, et remplit le schéma pipeline. La cascade de résolution des dates est appliquée pendant l'import et son résultat est stocké.

L'import est rejouable. Il vide et recharge le schéma pipeline à chaque passage. Le schéma app — vos tâches, vos sélections, vos corrections, vos notes — n'est jamais touché. Relancez-le sans crainte après chaque passe du pipeline adobe_mcp.

Quand relancer l'import ? Après un build-index, un build-content ou un propose-dates dans adobe_mcp. Les chiffres du pipeline bougent — les propositions de datation sont passées de 68 à 521 en une journée. L'interface affiche la date du dernier import : une donnée périmée doit se voir plutôt que mentir.

Lancer le backend

cd server
npm run dev      # rechargement à chaud, pour le développement
npm start        # sans rechargement

L'API écoute sur http://127.0.0.1:4310 par défaut — sur la boucle locale uniquement. Pour y accéder depuis un autre Mac du réseau, mettre PHOTO_UI_HOST=0.0.0.0 dans .env.

Vérifier qu'il répond :

curl http://127.0.0.1:4310/system/status

Lancer le frontend

Depuis la racine du dépôt, pas depuis server/ :

npm install      # la première fois
npm run dev      # http://localhost:5173

Pour une version compilée :

npm run build    # vérifie les types puis compile
npm run preview

Quand ça ne marche pas

L'import échoue en lisant les bases du pipeline

Le disque externe n'est pas monté, ou PIPELINE_DB_ROOT pointe ailleurs. Vérifiez que le dossier contient bien mcp-index.db, mcp-content.db, dating.db et documents.db.

L'import démarre puis échoue sur un chemin de fichier

PostgreSQL tourne dans un conteneur Docker et ne voit pas le disque externe. C'est normal et c'est prévu : les données transitent par le client Node, jamais par un COPY FROM côté serveur. Si une erreur mentionne un chemin introuvable côté base, c'est un bug — signalez-le.

Un album ne se retrouve pas par son nom

Les noms d'albums sont stockés en Unicode NFD sur macOS : Algès n'est pas la même chaîne selon la normalisation. L'import normalise, mais une requête tapée à la main peut ne rien trouver.

Une photo n'a pas d'image

Trois causes distinctes, que l'interface différencie : le disque n'est pas monté, le fichier a disparu, ou le format ne se rend pas. Le message le dit — il n'y a pas d'erreur générique.

Une date paraît fausse

Regardez sa couleur avant de conclure. Vert romain, c'est lu dans le fichier. Ambre italique préfixé ≈, c'est une inférence — souvent le nom du dossier, tapé à la main des années après la prise de vue. Violet gras préfixé ✓, c'est votre décision. Une inférence fausse se corrige ; une lecture fausse vient de l'appareil ou du scanner.
